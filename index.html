Problem definition

The puzzle becomes a search problem, so every algorithm works on the same Cube environment, written in Python and in JavaScript with identical logic.

ComponentDefinition
State54 sticker colours (6 faces x 9). About 4.3 x 10^19 reachable states.
Initial stateSolved cube plus k random quarter turns. The depth k sets the difficulty.
Actions12 quarter turns. Branching factor 12, or 11 after pruning the inverse of the last move.
TransitionOne fixed sticker permutation per action, generated from 3D geometry.
Goal testBoolean: every sticker has its solved colour.
Path cost1 per turn, so cost equals solution length.
DistanceConflict number c is the count of misplaced stickers. h = c / 20 never overestimates, since a turn fixes at most 20 stickers.

Notation and colours

Moves are named by the face they turn clockwise as seen from outside. A prime means counter-clockwise.

Solution methods

Each family is colour coded here and in the lab above.

Uninformed

BFS and UCS are complete and optimal with unit costs but need exponential memory. Iterative deepening repeats depth-limited DFS to keep optimality with linear memory.

Informed

Greedy orders by h. A* orders by g + w h, optimal when w is 1. IDA* applies iterative deepening to the f threshold.

Local search

Hill climbing takes the neighbour with fewest conflicts, with sideways moves and random kicks. Annealing accepts worse states with probability exp(-dE/T) as T cools.

Genetic algorithm

Individuals are fixed-length action sequences. Fitness is a large number minus path cost when a prefix solves the cube, else a half-large score minus conflicts. Roulette or tournament selection returns parent pairs, then crossover and mutation. A seeded generator makes runs repeatable.

Report and documentation

Reading the results

BFS, UCS and IDS return optimal solutions, but nodes grow about 11 times per extra move, so they stop being practical past depth 6. A* with the admissible heuristic stays optimal and expands far fewer nodes. The heuristic is weak because the cube has long plateaus, so weighted A* and greedy trade optimality for speed and can still stall. Hill climbing is fast and often stuck, annealing escapes more plateaus but returns long paths. The genetic algorithm needs no search tree and reports a solution when conflicts reach 0, keeping the shortest sequence seen.
